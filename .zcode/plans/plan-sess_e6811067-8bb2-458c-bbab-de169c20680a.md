## 🎯 OPTIMASI #1: Query Database renderLaporan() - CRITICAL

### Masalah Saat Ini:
```javascript
// Baris 1752-1777 - Query berulang-ulang + filter manual di loop
const allTrans = await db.transaksi.toArray();
const beli = allTrans.filter(...).reduce(...)  // filter + reduce
const jual = allTrans.filter(...).reduce(...)  // filter + reduce lagi
// Untuk setiap item transaksi, cari transaksi-nya satu per satu
for(const it of items){
  const tr = allTrans.find(t=>t.id===it.transaksiId); // O(n) dalam loop!
}
```

### Solusi Optimasi:
1. **Satu query semua transaksi** → simpan di variabel
2. **Buat map index** untuk lookup O(1): `transMap[t.id] = t`
3. **Group by tanggal sekali pass**, bukan filter berkali-kali
4. **Filter hanya sekali**, gunakan untuk semua perhitungan

**Estimasi Peningkatan:** 5-10x lebih cepat untuk 1000+ transaksi

## 🎯 OPTIMASI #3: Transaction Batch - saveTransaksi() - HIGH

### Masalah Saat Ini:
```javascript
async function saveTransaksi(){
  // Operasi database satu-satu (sequential)
```


## 🎯 OPTIMASI #5: DocumentFragment Rendering - MEDIUM

### Masalah Saat Ini:
```javascript
// innerHTML dengan string concatenation
card.innerHTML = list.map(item => `...`).join('');
// Menghancurkan & buat ulang seluruh DOM
```

### Solusi Optimasi:
Gunakan DocumentFragment untuk batch DOM insert:
```javascript
const fragment = document.createDocumentFragment();
list.forEach(item => {
  const el = document.createElement('div');
  el.textContent = ...;
  fragment.appendChild(el);
});
card.appendChild(fragment);
```

**Estimasi Peningkatan:** Lebih smooth, mengurangi layout thrashing
