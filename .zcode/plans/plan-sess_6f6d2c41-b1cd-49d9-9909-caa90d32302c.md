# Rencana Interactive Smoke Test - Kasir Solo Rosok

## Tujuan
Melakukan smoke test interaktif menyeluruh pada aplikasi Kasir Solo - Rosok di folder `rosok/` untuk memverifikasi:
1. Semua fitur inti berfungsi dengan benar
2. Bug fixes (Bug #1-#4) bekerja dengan baik
3. New features (Void transaction, Loading indicator) berfungsi
4. Security improvements (XSS prevention) efektif
5. Performance optimizations tidak menyebabkan regresi

## Metodologi
Menggunakan **Browser Use skill** untuk:
- Membuka aplikasi di browser secara otomatis
- Melakukan klik, input data, dan navigasi seperti user asli
- Memverifikasi hasil visual dan data
- Melakukan screenshot untuk dokumentasi

## Langkah Persiapan
1. Start local HTTP server: `python3 -m http.server 8080` di direktori `C:\Users\Admin\Documents\kasol\rosok`
2. Buka `http://localhost:8080` di browser via Browser Use
3. Verify service worker registration dan PWA elements

## Test Scenarios (Urutan Eksekusi)

### A. Initial State & Navigation
- Verify splash screen tidak ada (sudah dihapus)
- Check trial badge muncul di header
- Verify 5 navigation tabs: Dashboard, Transaksi, Stok, Riwayat, Laporan, Pengaturan
- Check dashboard summary (harus 0 jika data kosong)

### B. Kas Shift Management (Test Bug #1 Fix)
**Tujuan**: Verify `hitungKasSistemSejak()` menghitung kas dengan benar
1. Klik tab "Transaksi" → harus prompt buka kas
2. Buka kas dengan modal awal Rp 500.000
3. Verify kas status card: "🔓 Kas Sedang Buka"
4. Lakukan beberapa transaksi
5. Tutup kas → verify perhitungan selisih benar
6. Check riwayat buka/tutup kas di tab Laporan

### C. Transaction Flow (Test Bug #2 & #3 Fixes)
**Tujuan**: Verify double submit prevention & decimal support

#### C1. Pembelian (Beli Rosok)
1. Buka kas terlebih dahulu (jika belum)
2. Tab Transaksi → pilih "🛒 Beli dari Warga"
3. Pilih kategori (misal: "Kardus")
4. Timbang dengan berat desimal: 2.5 kg (test Bug #3: fmtRupiah decimal)
5. Tambah ke keranjang
6. Lanjut ke step 2 (pembayaran)
7. Test 3 metode: Tunai, Transfer, Tempo
8. **Kritis**: Klik tombol simpan berkali-kali cepat → verify tidak double submit (Bug #2)
9. Verify stok bertambah setelah transaksi

#### C2. Penjualan (Jual Rosok)
1. Tab Transaksi → pilih "📦 Jual ke Bandar"
2. Pilih kategori yang ada stoknya
3. Timbang → verify stok cukup check
4. Jika stok kurang → harus dapat toast error
5. Submit transaksi
6. Verify stok berkurang

### D. Stock Management
1. Tab Stok → verify list kategori dengan stok
2. Tambah kategori baru:
   - Nama: "Test Category"
   - Harga beli: 2000, Harga jual: 1500 → harus error (Bug #4: harga jual < harga beli)
   - Harga beli: 2000, Harga jual: 2500 → berhasil
3. Edit kategori → ubah harga
4. Nonaktifkan kategori

### E. Void Transaction (New Feature)
1. Dari riwayat transaksi → pilih salah satu transaksi
2. Klik "❌ Batal Transaksi (Void)"
3. Konfirmasi dua kali
4. Verify:
   - Stok dikembalikan ke kondisi sebelum transaksi
   - Kas mutation dihapus
   - Transaksi tetap ada tapi ditandai [DIBATALKAN]
5. Check audit trail di detail transaksi

### F. Reports & Calculations
1. Tab Laporan → check summary setelah beberapa transaksi
2. Verify:
   - Total Pembelian = jumlah semua transaksi beli
   - Total Penjualan = jumlah semua transaksi jual
   - Laba Kotor = Penjualan - Pembelian
   - Kas Saldo = saldo kas sekarang
3. Check bar chart 7 hari terakhir
4. Check Top 5 kategori terlaris
5. Check utang/piutang tempo list

### G. Data Management
1. Export data → download file JSON
2. Import data → pilih file yang didownload tadi
3. Verify data tetap sama
4. Reset data → konfirmasi dua kali → verify semua data kosong

### H. Security Test (XSS Prevention)
1. Di tab Stok → tambah kategori dengan nama: `<script>alert('XSS')</script>`
2. Verify tidak ada alert (XSS prevented)
3. Nama kategori harus ditampilkan sebagai text biasa (escaped)
4. Test di field lain: nama kontak, catatan transaksi

### I. PWA & Offline Features
1. Check browser console → verify service worker registered
2. Check manifest.json loaded
3. Test offline mode (disconnect network)
4. Reload page → aplikasi tetap bisa dibuka (dari cache)
5. Reconnect → verify sync kembali

### J. Edge Cases
1. Test dengan data kosong (setelah reset)
2. Test input negatif di berat/uang → harus ditolak
3. Test pagination: Riwayat transaksi → "Muat Lebih Banyak"
4. Test dengan ribuan data (jika memungkinkan)

## Success Criteria
- ✅ Bug #1 (kas calculation): FIXED - `hitungKasSistemSejak()` hanya hitung kas sejak shift dibuka
- ✅ Bug #2 (double submit): FIXED - `isSaving` flag mencegah double submit
- ✅ Bug #3 (decimal Rupiah): FIXED - `fmtRupiah()` support 2 desimal
- ✅ Bug #4 (price validation): FIXED - harga jual harus > harga beli
- ✅ Security: XSS prevention dengan `escapeHtml()` bekerja
- ✅ New feature: Void transaction berfungsi dengan audit trail
- ✅ Performance: Optimasi DOM caching & database queries tidak menyebabkan error
- ✅ PWA: Service worker berfungsi, offline mode works

## Expected Output
1. Laporan hasil smoke test (pass/fail untuk setiap test case)
2. Screenshot dokumentasi (jika ada error)
3. Rekomendasi jika ada issue ditemukan
